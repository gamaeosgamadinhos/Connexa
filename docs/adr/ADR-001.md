# ADR-001: Escolha da Arquitetura Base para o Projeto Connexa

## 1. Contexto
Para o início da Sprint 1 do projeto Connexa, a equipe precisava definir a tecnologia principal e o template de arquitetura que servirá de base para a construção do produto. As opções fornecidas como padrão para a disciplina de Engenharia de Software foram: `connexa-modelo-java`, `connexa-modelo-dotnet` e `connexa-modelo-node`. A decisão precisava considerar os conhecimentos prévios do grupo e a eficiência para planejar, especificar e executar tarefas em conjunto com um agente de IA no VS Code.

## 2. Decisão
A equipe decidiu adotar a arquitetura baseada em **Node.js**. O repositório oficial do projeto será instanciado a partir do template `connexa-modelo-node`.

## 3. Motivo da Escolha
* **Familiaridade técnica:** A equipe possui domínio em JavaScript, HTML e CSS, o que elimina a curva de aprendizado com uma nova linguagem estrutural e permite focar nas práticas de engenharia exigidas (rastreabilidade, especificação e revisão).
* **Agilidade com a Inteligência Artificial:** O ecossistema Node.js é leve, amplamente documentado e possui excelente suporte por agentes como o GitHub Copilot. Isso otimiza a geração de código e a precisão das ferramentas do servidor MCP.
* **Ciclo de Testes:** A configuração de testes no ecossistema Node (como Jest) facilita a aplicação do ciclo "vermelho → verde" e das etapas de sabotagem controlada estabelecidas na disciplina.

## 4. Consequências
* A equipe fará a configuração inicial clonando o template `connexa-modelo-node`.
* As validações de CI/CD (GitHub Actions) no repositório exigirão que os testes do ecossistema Node passem com sucesso (verde) antes de permitir o *merge* de qualquer Pull Request na branch `main`.
* Os comandos de execução de testes repassados para a IA durante o detalhamento das Tasks deverão utilizar o padrão do gerenciador de pacotes do Node (ex: `npm run test`).
